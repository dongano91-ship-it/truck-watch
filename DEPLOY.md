# Перенос в облако (GitHub Actions)

Скрипт будет запускаться в облаке по расписанию — компьютер можно выключать.

## Что важно понять заранее

GitHub Actions — бесплатный сервис, но у него есть особенность: **точность
расписания примерно ±5 минут**, а в час пик бывает и 15. Это не ошибка,
а как устроен планировщик GitHub. Для «машина приехала» сойдёт, для
секундной точности — нет (тогда нужен сервер, ~200 ₽/мес).

Второе: бесплатные минуты считаются по 1 минуте за запуск.

| Расписание | Запусков в сутки | Минут в месяц | Комментарий |
|---|---|---|---|
| каждые 5 мин | 288 | ~8600 | помещается только в **публичном** репозитории (там минуты бесплатны) |
| каждые 15 мин | 96 | ~2900 | приватный репозиторий: чуть больше лимита 2000 |
| каждые 30 мин | 48 | ~1440 | приватный: помещается с запасом |

**Выбор:** нужна скорость — делайте репозиторий **публичным** и оставляйте
5 минут. Нужна приватность — **приватный** и 30 минут.

## Шаг 1. Аккаунт GitHub

1. Откройте [github.com](https://github.com) → **Sign up**.
2. Подтвердите почту — без этого Actions не включатся.

## Шаг 2. Новый репозиторий

1. Кнопка **+** → **New repository**.
2. Имя: `truck-watch`.
3. Выберите **Public** (для 5-минутного расписания) или **Private**.
4. **Create repository**.

## Шаг 3. Загрузить файлы

В пустом репозитории нажмите **uploading an existing file** и перетащите:

- `watcher.py`
- `config.json`
- `state.json`
- `subscribers.json` (если есть)

Затем **Commit changes**.

> Папку `.github` с файлом workflow тоже надо загрузить. Если через
> «upload file» она не цепляется — создайте файл вручную:
> **Add file → Create new file**, имя `.github/workflows/watch.yml`,
> и вставьте содержимое из файла в проекте.

## Шаг 4. Секреты

**Settings → Secrets and variables → Actions → New repository secret.**

Добавьте три секрета:

| Имя | Значение |
|---|---|
| `TELEGRAM_TOKEN` | токен бота от BotFather |
| `TELEGRAM_CHAT_ID` | chat_id группы (например `-5466356396`) |
| `SHEET_URL` | ссылка на Google-таблицу целиком |

> Токен и ссылку НЕ надо писать в `config.json` — в облаке они подставятся
> из секретов автоматически. В файле `config.json` их можно оставить
> пустыми.

## Шаг 5. Включить Actions

Вкладка **Actions** → включите workflow, если GitHub предложит.
Дальше кнопка **truck-watch → Run workflow** — это первый ручной запуск,
он покажет, всё ли работает.

Через минуту проверьте Telegram: должно прийти уведомление, если что-то
изменилось в таблице (или ничего, если изменений не было — это норма).

## Как это работает

Каждые N минут GitHub:
1. открывает ваш репозиторий,
2. запускает `python watcher.py --once`,
3. скрипт читает таблицу, сравнивает с `state.json`, шлёт события,
4. если состояние изменилось — коммитит `state.json` обратно.

Следующий запуск видит обновлённое состояние и не повторяет события.

## Проверка, что живо

- **Actions** → список запусков: зелёные галочки = работает.
- Красный крестик → откройте запуск и смотрите лог шага «Проверить таблицу».

## Чего в облаке не будет

- **Подписка новых людей через сообщение боту** работает, но с задержкой:
  человек написал, а подхватится при следующем запуске (5–30 минут).
- **Кнопка «Пауза»** — только через отключение workflow.

## ⚠️ Не запускайте два слежения сразу

Локальный `2-ЗАПУСК.bat` и облако — это два независимых «наблюдателя».
Если работают оба:

- придут **дубли** уведомлений (каждый заметит изменение сам);
- Telegram разрешает получать сообщения боту только одному клиенту —
  второй начнёт получать ошибку `409 Conflict`, и новые подписчики
  не будут регистрироваться.

**Правило:** включили облако — закройте окно `2-ЗАПУСК.bat` на компьютере.

## Если нужна точность

GitHub не умеет чаще 5 минут и не гарантирует время. Для «сразу после
события» нужен дешёвый сервер (VPS за 200–300 ₽/мес) — там скрипт крутится
непрерывно, как на вашем компьютере, только всегда включён.
